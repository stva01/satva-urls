01
Reef_ID only works for one sourceblocks splits

Reef_ID is 100% missing for every source except Reef_Check, where it's 100% present. It cannot be used as the reef-level grouping key for the full dataset.

Fix: use Site_ID instead — populated for all 9 sources (12,702 unique values) — but verify it matches the granularity you need before relying on it.

03
Rows are duplicated — mostly in Reef_Checkcritical

The original schema is relational; this flat file joined survey + substrate-cover tables together. That join exploded one real survey into several rows — one per substrate type.

28,821 Reef_Check rows are really only 14,475 actual survey events (99.6% share a Sample_ID with another row). Percent_Bleaching is copy-pasted identically across the duplicates.

Any row-level count or average right now roughly double-counts Reef_Check bleaching values. Deduplicate to one row per Sample_ID before any bleaching-level analysis.
04
Percent_Bleaching isn't one consistent measurementcomparability

Bleaching_Level is only ever recorded as "Population" for Reef_Check — every other source leaves it blank (nd), even when their Percent_Bleaching values are present.

Per the source documentation, Percent_Bleaching itself is computed two different ways: Reef Check averages 4 transect segments; other sources average a "bleaching code." Same column name, different method.

Treat Percent_Bleaching as source-conditional, not a single homogeneous target — always model with Data_Source as a covariate.

06
Missing values are encoded as the string "nd"gotcha

Even numeric columns (Percent_Bleaching, Depth_m, all SSTA/TSA fields) use the literal text "nd" for missing — not blank, not NaN.

Standard .isnull() checks will silently miss this. Every script must explicitly match the string "nd" before doing numeric work.

Before Week 2

  1. Deduplicate to one row per real survey (Sample_ID) before any bleaching statistics
  2. Use Site_ID, not Reef_ID, as the reef-level split key — validate it first
  3. Confirm provenance of Nuryana and Setiawan before citing "7 sources"
  4. Always include Data_Source as a covariate when using Percent_Bleaching
  5. Handle missingness per-source/per-field, not with one global rule

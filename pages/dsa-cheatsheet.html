Pattern Recognition:
A DSA Field Manual

You already know how to code. What you've lost touch with is pattern recall under pressure — the half-second where a problem statement should trigger "oh, this is a sliding window." This manual rebuilds that reflex for the three families you'll almost certainly see tomorrow: hashmaps, two pointers, sliding window.

The meta-framework

Use this on every single question, even ones this manual doesn't cover.

Interviewers grade the process more than the final code. Narrate these five steps out loud, in order, every time:

1 · Clarify

Restate the problem in your own words. Ask about input size, duplicates, negative numbers, sorted-ness, empty input, and what to return on no valid answer. This alone signals seniority.

2 · Brute force

Say the obvious O(n²) or O(n³) approach out loud, even if you won't code it. It proves you understand the problem and gives you a baseline to optimize from and a way to sanity-check your final answer.

3 · Find the bottleneck

Ask: "what is my brute force redoing that it doesn't need to?" Usually it's redundant lookups (→ hashmap), redundant nested scanning over a sorted/orderable structure (→ two pointers), or redundant recomputation over a contiguous range (→ sliding window).

4 · Code the optimal

Write it incrementally. Talk while you type. Name variables meaningfully (left/right, not i/j, once roles matter).

5 · Dry run + edge cases

Trace one small example by hand. Then state complexity and check empty input, single element, all-duplicates, and the smallest/largest constraint value.

Why this matters more than the code

Silence is the worst thing you can do in a DSA round. An interviewer who hears your reasoning can nudge you toward the right pattern even if you're stuck. An interviewer watching you stare at the screen has nothing to work with.

Pattern 01 · Hashmaps

Trade space for time by turning "search" into "lookup."

The core intuition

Any time your brute force re-scans the array to answer "have I seen X before?", "how many times has X appeared?", or "what's paired with X?" — a hashmap turns that O(n) re-scan into an O(1) lookup. The trade is always O(n) extra space for O(n) time saved. If you hear yourself say "for each element, check the rest of the array," a hashmap is almost always the fix.

Reach for it when you see...

  • "Find a pair / triplet that sums to X" (unsorted array)
  • "Count frequency," "find duplicates," "group by some key"
  • "Have I seen this before" — existence or first-occurrence questions
  • Anagram / permutation comparisons (character or word frequency signatures)
  • Prefix-sum problems ("subarray sums to K") — store prefix sums, not raw values

Python toolkit

from collections import defaultdict, Counter

# Plain dict — get() avoids KeyError, gives you a default inline
d = {}
d[key] = d.get(key, 0) + 1

# defaultdict — auto-creates missing keys with a default factory
# CAUTION: reading a missing key with defaultdict CREATES it (see pitfalls)
groups = defaultdict(list)
groups[key].append(value)

counts = defaultdict(int)
counts[key] += 1

# Counter — purpose-built frequency map, has extra powers
c = Counter(nums)          # {value: count}
c.most_common(k)           # top-k by frequency, O(n log k)
c1 - c2                    # subtract counts (drops zero/negative results)
c1 & c2                    # min of counts per key — great for anagram checks

# set — when you only care about membership, not count
seen = set()
if x in seen: ...          # O(1) average
seen.add(x)

Generic template

def solve(nums):
    seen = {}                      # value/key -> index, count, or bool
    for i, num in enumerate(nums):
        complement = target - num  # or whatever "partner" you need
        if complement in seen:
            return [seen[complement], i]
        seen[num] = i              # record AFTER checking — avoids self-match
    return []
Note the ordering trick

Check for the complement before inserting the current element. This single line is what prevents a value from pairing with itself and is the #1 off-by-logic bug in hashmap two-sum variants.

Problem set

Two Sum — NeetCode #1 · Striver Sheet Easy

Ask

Return indices of the two numbers that add up to a target.

Brute → Better → Optimal

Brute O(n²): check every pair. Optimal O(n): one-pass hashmap storing value → index; look up target - num as you go (see template above). No "better" tier needed — hashmap gets you straight to optimal in one pass.

Why it matters

It's the canonical "one seen-before check replaces a nested loop" problem. Every interviewer expects the one-pass version, not two passes.

Group Anagrams — NeetCode Blind 75 · Striver Sheet Medium

Ask

Group strings that are anagrams of each other.

BruteO(n²·k)

Compare every string against every other string for anagram equality.

BetterO(n·k log k)

Sort each string's characters to build a canonical key; hashmap key → list of original strings.

OptimalO(n·k)

Skip sorting — build a 26-length character-count tuple as the key instead. Same grouping, no log k factor.

Key idea

The "key" you hash on doesn't have to be the raw data — it just has to be canonical: two anagrams must always produce the identical key.

Top K Frequent Elements — NeetCode Blind 75 Medium

Ask

Return the k most frequent elements in the array.

BruteO(n log n)

Count frequencies with a hashmap, then sort the (value, count) pairs by count.

BetterO(n log k)

Count, then maintain a min-heap of size k over the counts — never sort the whole thing.

OptimalO(n)

Bucket sort: index i of a buckets array holds all values with frequency i (frequency is bounded by n, so buckets has n+1 slots). Walk buckets from the back.

Pattern to remember

"Count first, then rank by count" is a two-stage pattern: hashmap for counting is almost never the part that needs optimizing — the ranking step is. Bucket sort applies whenever the ranking key (frequency) is bounded by n.

Longest Consecutive Sequence — NeetCode Blind 75 · Striver Sheet Medium

Ask

Find the length of the longest run of consecutive integers, unsorted input, required O(n).

BruteO(n²)

For each number, keep checking num+1, num+2... by scanning the array each time.

BetterO(n log n)

Sort first, then walk once counting consecutive runs.

OptimalO(n)

Put everything in a hashset. For each number, only start counting a sequence if num - 1 is NOT in the set (i.e., you're at a true sequence start). Then walk forward with a while loop.

The trick that makes it O(n)

Every number is only ever "walked" once across the whole algorithm, because you only start a walk from sequence starts. That single if num - 1 not in set guard is what turns a naive O(n²) hashset walk into O(n) amortized.

Subarray Sum Equals K — NeetCode · Striver Sheet Medium

Ask

Count the number of contiguous subarrays that sum exactly to k. (Note: array can contain negatives, which is exactly why sliding window doesn't work here — see the decision tree below.)

BruteO(n²)

Try every subarray, sum it, compare to k.

OptimalO(n)

Running prefix sum + hashmap of {prefix_sum: count_of_times_seen}. At index i, if prefix_sum - k has been seen before, every one of those earlier positions marks a valid subarray ending at i.

def subarraySum(nums, k):
    count, prefix_sum = 0, 0
    seen = {0: 1}  # empty prefix sums to 0 — seeds subarrays starting at index 0
    for num in nums:
        prefix_sum += num
        count += seen.get(prefix_sum - k, 0)
        seen[prefix_sum] = seen.get(prefix_sum, 0) + 1
    return count

Why {0: 1} seed

It accounts for the case where the subarray from index 0 itself sums to k — without it you'd silently undercount.

Pattern 02 · Two Pointers

Exploit order (sorted arrays, linked lists) to eliminate a nested loop entirely.

The core intuition

Two pointers works when moving one pointer inward gives you provable, monotonic information about the rest of the search space — so you never need to re-check what you've already ruled out. It has three distinct shapes, and knowing which shape you're in is half the battle:

ShapeMovementUsed for
Convergingleft starts at 0, right at n-1, move inwardsorted-array pair sums, palindrome checks, container/area problems
Same-directionboth start at 0, move forward at different ratesin-place dedup/partition, merging two arrays
Fast & slowfast moves 2 steps, slow moves 1cycle detection, finding the middle of a linked list

Reach for it when you see...

  • The array is already sorted (or you're free to sort it — check if order matters for the answer)
  • "Pair/triplet sums to X" and the array is sorted → two pointers beats hashmap on space (O(1) vs O(n))
  • Palindrome checks, reversing in place
  • Linked-list cycle, middle-of-list, "nth from the end"
  • In-place array modification (remove duplicates, partition around a pivot)

Converging-pointer template

def two_pointer(arr):
    left, right = 0, len(arr) - 1
    while left < right:
        current = arr[left] + arr[right]     # or whatever your condition needs
        if current == target:
            # record answer
            left += 1
            right -= 1
        elif current < target:
            left += 1     # need a bigger sum -> only moving left can increase it
        else:
            right -= 1    # need a smaller sum -> only moving right can decrease it
    return result

Fast & slow template (Floyd's)

def has_cycle(head):
    slow = fast = head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
        if slow is fast:
            return True
    return False

Problem set

Two Sum II — Input Array Is Sorted — NeetCode · Striver Sheet Medium

Ask

Same as Two Sum, but the array is sorted and you must use O(1) extra space.

BruteO(n²)

Nested loop over all pairs.

BetterO(n) time, O(n) space

Hashmap approach from Two Sum still works — but wastes the fact that the array is sorted.

OptimalO(n) time, O(1) space

Converging two pointers using the template above — sum too small → move left up, sum too big → move right down.

Interview signal

This is the single best problem to say out loud: "I could use a hashmap like classic Two Sum, but since it's sorted, two pointers gets me the same time complexity with no extra space." That sentence alone demonstrates real pattern fluency.

Valid Palindrome — NeetCode · Striver Sheet Easy

Ask

Check if a string is a palindrome, ignoring non-alphanumeric characters and case.

Approach

Converging pointers from both ends; skip non-alphanumeric characters with an inner while loop on each side before comparing. O(n) time, O(1) space — no need to build a cleaned copy of the string first.

Pitfall

Forgetting to lowercase both characters before comparing, and forgetting the bounds check (left < right) inside the inner skip-loops so you don't walk pointers past each other.

Container With Most Water — NeetCode Blind 75 · Striver Sheet Medium

Ask

Given heights, find two lines that with the x-axis form the container holding the most water.

BruteO(n²)

Try every pair of lines, compute area = min(height) × width.

OptimalO(n)

Converging pointers. Always move the pointer at the shorter line inward.

The intuition that unlocks it

Width only ever shrinks as pointers converge, so area can only grow if height grows. The shorter line is capping your current area — moving the taller line inward can only hurt you (width drops, height cap unchanged or worse), while moving the shorter line inward is the only move that has a chance of finding a taller line and raising the cap.

3Sum — NeetCode Blind 75 · Striver Sheet Medium

Ask

Find all unique triplets that sum to zero.

BruteO(n³)

Three nested loops, dedupe with a set of sorted tuples.

OptimalO(n²)

Sort the array. Fix one element with an outer loop, then run converging two pointers on the remainder for the other two.

def threeSum(nums):
    nums.sort()
    res = []
    for i in range(len(nums)):
        if i > 0 and nums[i] == nums[i-1]:
            continue                       # skip duplicate anchors
        left, right = i + 1, len(nums) - 1
        while left < right:
            total = nums[i] + nums[left] + nums[right]
            if total < 0:
                left += 1
            elif total > 0:
                right -= 1
            else:
                res.append([nums[i], nums[left], nums[right]])
                left += 1
                right -= 1
                while left < right and nums[left] == nums[left-1]:
                    left += 1               # skip duplicate second element
    return res

The escalation to remember

3Sum = "fix one, two-pointer the rest." This same escalation trick generalizes to 4Sum (fix two, two-pointer the rest, O(n³)) — mention that generalization if asked as a follow-up.

Trapping Rain Water — NeetCode Blind 75 · Striver Sheet Hard

Ask

Given elevation heights, compute total trapped rainwater.

BruteO(n²)

For each bar, scan left and right to find the max on each side.

BetterO(n) time, O(n) space

Precompute left_max[] and right_max[] arrays in two passes, then a third pass computes trapped water per index.

OptimalO(n) time, O(1) space

Converging pointers with two running maxes (left_max, right_max) instead of arrays. Move whichever pointer has the smaller running max — water at that position is bounded by that smaller max.

Why this one feels hard

It's genuinely a step up from Container With Most Water because you're accumulating an answer at every position, not just picking one final pair. If you get this in the interview, explicitly say you're doing the O(n)/O(n) two-array version first, then optimizing space — that staged narration is worth real credit even if you don't finish the O(1)-space version.

Remove Duplicates from Sorted Array — NeetCode · Striver Sheet Easy

Ask

Remove duplicates in-place from a sorted array, return the new length.

Approach — same-direction pointers

slow marks the last confirmed-unique position; fast scans ahead. When nums[fast] != nums[slow], advance slow and copy the value in. This is the template for a whole family of "partition/compact array in place" problems (move zeroes, remove element, etc).

Linked List Cycle — NeetCode Blind 75 · Striver Sheet Easy

Ask

Detect if a linked list has a cycle.

Approach — Floyd's fast & slow (see template above)

If there's a cycle, fast eventually laps slow inside it — they're guaranteed to meet within one full loop of the cycle. If there's no cycle, fast simply hits None.

Common follow-up

"Find the start of the cycle" — after slow and fast meet, reset one pointer to head and move both one step at a time; they meet again exactly at the cycle's start. Worth memorizing the fact even if not the full proof.

Pattern 03 · Sliding Window

Two pointers' cousin, specialized for contiguous subarrays/substrings.

The core intuition

When your brute force recomputes something over every contiguous subarray from scratch, a sliding window lets you incrementally update that computation as the window's edges move — instead of a nested loop recomputing the whole range each time, you add one element on the right and (sometimes) remove one on the left. It only works when growing/shrinking the window lets you cheaply update your running answer — sums, counts, and frequency maps are cheap to update; "max of window" is not (that needs a monotonic deque, see below).

Reach for it when you see...

  • "Longest / shortest / max / min contiguous subarray or substring" satisfying some condition
  • A constraint that only gets violated by growing the window and only gets fixed by shrinking it (monotonic validity) — this is the litmus test
  • Explicit fixed window size k ("max sum of any subarray of size k")
  • Watch out: if the array has negative numbers and you need a sum, sliding window's "shrink when too big" logic breaks — that's a prefix-sum + hashmap problem instead (see Subarray Sum Equals K above)

Fixed-size window template

def fixed_window(nums, k):
    window_sum = sum(nums[:k])
    best = window_sum
    for right in range(k, len(nums)):
        window_sum += nums[right] - nums[right - k]  # add new, drop the one that fell off
        best = max(best, window_sum)
    return best

Variable-size window template (the one to memorize)

def variable_window(s):
    left = 0
    window_state = {}          # or a running count/sum — whatever tracks validity
    best = 0
    for right in range(len(s)):
        # 1. expand: fold s[right] into window_state
        window_state[s[right]] = window_state.get(s[right], 0) + 1

        # 2. shrink while the window is invalid
        while not is_valid(window_state):
            window_state[s[left]] -= 1
            if window_state[s[left]] == 0:
                del window_state[s[left]]
            left += 1

        # 3. window [left, right] is now valid — update answer
        best = max(best, right - left + 1)
    return best
Say this out loud in the interview

"Right pointer expands the window every iteration; left pointer only advances when the window becomes invalid — so overall each pointer moves at most n times, giving O(n) total even though it looks like a nested loop." That sentence pre-empts the interviewer's most common follow-up question about this pattern's complexity.

Problem set

Maximum Sum Subarray of Size K — classic warm-up / Striver Sheet Easy

Ask

Find the maximum sum of any contiguous subarray of exactly size k.

BruteO(n·k)

For each starting index, sum the next k elements from scratch.

OptimalO(n)

Fixed-size window template above — each slide adds one element and removes one.

This is the "hello world" of sliding window — if the mechanics here aren't automatic, drill this one first before anything else in this section.

Longest Substring Without Repeating Characters — NeetCode Blind 75 · Striver Sheet Medium

Ask

Find the length of the longest substring with no repeated characters.

BruteO(n³)

Check every substring for uniqueness with an inner set-building loop.

BetterO(n²)

Fix left, extend right until a duplicate appears — but restart the whole inner scan from a fresh set each time left moves.

OptimalO(n)

Variable window with a hashmap of char → last seen index. On a repeat, jump left directly to last_seen[char] + 1 instead of shrinking one step at a time.

The upgrade worth knowing

Most people first learn this with a while-shrink loop (removing from a set one at a time). The last-seen-index version is strictly better — it jumps left in one step instead of looping — and interviewers notice when you offer it as a follow-up optimization.

Longest Repeating Character Replacement — NeetCode Blind 75 · Striver Sheet Medium

Ask

Given a string and an integer k, find the longest substring achievable by replacing at most k characters with any other character, such that the substring becomes all-same-character.

Approach — variable window with a validity formula

Track a frequency count of characters in the window and the count of the single most frequent character (max_freq). The window is valid exactly when (window_length - max_freq) <= k — i.e., the number of characters you'd need to replace doesn't exceed the budget.

Subtle but important

max_freq is allowed to go stale (not decrease when you shrink the window) — the window can never shrink below its best-ever size anyway, so a stale max_freq never produces a wrong answer, only a temporarily non-shrinking window. This is the detail that trips people up when re-deriving this on the spot.

Minimum Window Substring — NeetCode Blind 75 · Striver Sheet Hard

Ask

Find the smallest substring of s that contains every character of t (with multiplicity).

BruteO(n²·m)

Check every substring against t's requirements from scratch.

OptimalO(n + m)

Variable window: expand right until the window satisfies all of t's character requirements, then shrink left as far as possible while it's still valid, recording the best (smallest) window each time it's valid.

Why this is the "boss level" sliding window problem

It combines both shrink-while-valid (like Longest Repeating Character Replacement) and grow-until-valid (unlike most other window problems, which only shrink-while-invalid). Track a need counter (from t) and a have counter matched-so-far; shrink only while every requirement in need is still met.

Longest Substring with At Most K Distinct Characters — NeetCode · a.k.a. "Fruit Into Baskets" (K=2) Medium

Ask

Find the longest substring containing at most k distinct characters.

Approach

Variable window with a frequency hashmap. Expand right, incrementing counts; while len(freq_map) > k, shrink left, decrementing counts and deleting keys that hit zero. This is the most "textbook" application of the variable-window template — if you're rusty, dry-run this one by hand before tomorrow.

Sliding Window Maximum — NeetCode Blind 75 · Striver Sheet Hard

Ask

Return the maximum of every fixed-size window of size k as it slides across the array.

BruteO(n·k)

Scan all k elements for the max at every window position.

BetterO(n log k)

Max-heap of (value, index) pairs, lazily discarding indices that have fallen out of the window.

OptimalO(n)

Monotonic decreasing deque storing indices. Before pushing a new index, pop from the back while its value is smaller than the incoming value (they can never be the max while a bigger, newer element is in range). Pop from the front when the front index falls outside the window.

Why plain sliding window state doesn't work here

Unlike sum/count, "max" isn't cheaply un-doable when an element leaves the window on the left — you'd have to rescan. The monotonic deque sidesteps this by only ever keeping candidates that could still become the max later, which is why this problem is the standard bridge from "sliding window" to "monotonic deque" as its own pattern.

Pitfalls checklist

The specific bugs that actually happen under interview pressure — skim this right before you go in.

  • Hashmap: checking complement in seen AFTER inserting the current element lets a value pair with itself — always check before inserting.
  • defaultdict: merely reading a missing key (e.g. inside an if check) silently creates it. Use plain dict + .get() if you need to test existence without side effects.
  • Two pointers: in 3Sum-style problems, forgetting to skip duplicate values at both the outer anchor and the inner left/right pointers produces duplicate triplets.
  • Two pointers: off-by-one on the stopping condition — decide up front whether it's left < right or left <= right and justify it against whether a single element can be a valid answer on its own.
  • Sliding window: using if instead of while to shrink — a window can need to shrink by more than one element per step.
  • Sliding window: negative numbers break "shrink when sum too big" logic — confirm constraints before assuming sliding window applies to a sum problem.
  • General: always test the empty input and single-element input cases out loud, even if you don't code them — interviewers listen for this.
  • General: state time and space complexity unprompted at the end — don't wait to be asked.

Before you walk in

You don't need to have every problem above memorized verbatim. You need the reflex: read the problem, hear yourself ask "what is my brute force redoing?", and land on hashmap / two pointers / sliding window within the first thirty seconds. That reflex is the entire point of this manual — everything else is repetition until it's automatic.

Talk through the meta-framework on every problem, even the ones that feel unfamiliar. Confidence tomorrow isn't going to come from having seen the exact question before — it's going to come from having a process that works regardless of which one they pick.
